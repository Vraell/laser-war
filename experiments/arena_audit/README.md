## Verdict

The arena was seriously hardened during the audit, but the current CI gate cannot
certify or deploy an AI update: its fixed 64-pair run is too short for its own SPRT
acceptance rule. Revision isolation, paired play, invalid outcomes, offsets, and
manifests are now credible. Statistical stopping, independent resource accounting,
and test-set independence remain the important blockers.

## Findings

### P0: the 64-pair release gate rejects an identical engine

The workflow runs 64 pairs per difficulty. `passesArenaGate()` requires the
non-regression SPRT to reach `accept-h1`; an inconclusive result fails. For 64
perfectly neutral pair scores, the current LLR is `2.906169`, just below the
`2.944439` acceptance boundary.

This is not theoretical. An end-to-end 64-pair Easy match of `HEAD` against the
same `HEAD` produced `60-8-60`, pentanomial `0-0-64-0-0`, then exited with
`Candidate failed the nonregression gate`. The gate is applied to every difficulty,
so unchanged Easy, Medium, and Hard prevent an Ultra-only improvement from shipping.

Concrete tests and fix:

1. Add a workflow-policy test asserting that an identical engine passes every
   configured release gate.
2. Do not run an SPRT for a fixed number of games and convert `inconclusive` into a
   final failure. Continue fresh opening pairs until H0 or H1 is accepted, subject
   to a declared maximum that reports `inconclusive`, not `regression`.
3. Calibrate expected run length before choosing CI limits. Merely changing 64 to
   65 handles the zero-variance control but not normal match variance.

### P1: the custom pentanomial SPRT is not independently validated

The new implementation derives both hypotheses by exponentially tilting the same
observed counts with a Jeffreys-style pseudocount. This is a custom plug-in model,
not a port with reference vectors from Stockfish Fishtest. Its unit tests show a
few expected statuses generated by the same implementation; they do not verify
type-I/type-II error, stopping behavior, or likelihood values against an external
implementation.

A no-draw Monte Carlo audit found the current 64-pair test effectively 100%
inconclusive from -20 through +20 true Elo. At 512 pairs, a true neutral engine was
still inconclusive in 73.2% of runs and accepted H1 in 26.1%. Long runs are not a
problem for SPRT, but a fixed short runner is.

Concrete tests and fix:

1. Port or directly reuse a reviewed pentanomial GSPRT implementation.
2. Validate LLR and decisions against published/reference result vectors.
3. Simulate Laser War's observed five-outcome distribution to verify alpha, beta,
   power, and average stopping length at each proposed Elo bound.
4. Keep per-difficulty and aggregate hypotheses explicit; do not use aggregate
   acceptance to hide a difficulty-specific regression.

### P1: the deterministic work budget is incomplete

The latest draft improves on self-reported search nodes by injecting an arena-owned
counter into seven authoritative rule methods. That is harder to game accidentally,
but every method entry has equal weight: a cheap cached call and a full SAT/route
solve both cost one unit. Pure AI evaluation, sorting, allocation, memoization,
endgame work, and computation inside one counted method remain unmeasured. A search
revision can therefore move substantial work across the counted boundary without
changing its nominal budget. A later profile property can also override the injected
`nodeLimit`.

The `time` resource is synthetic: `performance.now()` is replaced with a clock that
advances when queried. A change in clock-call frequency changes the effective budget,
so this mode cannot evaluate time-management improvements. The real 11-second move
limit is checked only after synchronous search returns; the process timeout is the
only preemptive kill.

Concrete tests and fix:

1. Mutation-test duplicate limits, uncounted solvers, work moved into helpers, and
   alternate clocks; every mutation must fail closed.
2. Run each move in a killable worker with a parent-enforced real deadline.
3. Maintain separate deterministic-work and real-time arenas. Use the latter for
   speed and time-management changes.
4. Report work, wall time, p95/p99, time forfeits, and completed depth for both sides.

### P1: the candidate controls the judge used to approve itself

Candidate and baseline executable bundles are isolated, but the arena harness,
statistics implementation, workflow, and integrity tests all come from the candidate
checkout. They are not included in the source manifest or pinned to a trusted base.
An AI patch can therefore accidentally modify its own scoring, opening selection,
budget adapter, or pass rule and then be judged by that modified code.

Concrete tests and fix:

1. Run release Elo from a reviewed, versioned harness artifact independent of the
   candidate branch, or require a separately approved harness hash.
2. Include the harness, statistics code, workflow policy, and opening generator in
   `ARENA_MANIFEST`.
3. Reject combined AI-plus-harness changes from claiming Elo until the harness change
   passes an identical-engine and known-inferior-engine qualification suite.

### P1: the Elo openings are narrow and repeatedly reused

CI now uses only generated openings. Generation deliberately preserves all shields
and samples only 0-10 quiet plies from fixed public seeds. Color swapping removes
first-player bias, but it does not make this a broad or independent position set.
Repeated optimization can overfit these exact openings, and tactical or damaged-
shield middlegames are represented only after self-play reaches them.

Concrete tests and fix:

1. Retain historical failures as deterministic tactical regressions, not Elo data.
2. Build a frozen, broad public book spanning quiet, forcing, asymmetric, damaged-
   shield, side-inverted, and late positions.
3. Keep an untouched holdout book and independent seed range for release confirmation.
4. Run short- and long-budget tests on different books before claiming Elo.

### P2: the 50,000-node CI budget lacks a runtime feasibility gate

The workflow currently assigns Ultra 50,000 self-reported nodes per move. Ultra
children receive two pairs, a 240-second process timeout, and at most four workers.
This is safer than the previous unbounded fan-out, but the timeout is not derived
from openings, plies, or measured p99 move cost. A valid child can still be killed
by host contention or expensive uncounted work.

Concrete tests and fix: run a preflight on the exact CI manifest, establish p50,
p95, p99, and total child duration, then derive concurrency and child deadlines from
measured capacity with headroom. Worker kills must remain infrastructure failures.

### P2: integrity tests still miss the most consequential negative controls

The new integration test covers identical pairing, truncation rejection, and offset
composition. It does not cover baseline timeout symmetry, source-adapter mutation,
mixed harness hashes, worker kills, opening corruption, node-counter bypass, real-
time enforcement, or the 64-pair SPRT contradiction.

Concrete tests and fix: promote the weak, slow, revision-sentinel, and statistical
probes in this directory into hermetic CI tests. Add one known-inferior engine that
must fail and one identical engine using the exact workflow policy that must pass.

## Verified defenses

The final snapshot successfully addresses several issues found earlier:

- Complete AI, tactics, endgame, engine, exact-route, and SAT dependencies load from
  each revision; a revision-only engine export resolved successfully.
- Candidate and baseline semantic rules hashes must match before Elo is measured.
- A no-ref working tree is frozen into an immutable candidate snapshot before child
  processes start, and child bundle hashes are checked for consistency.
- Truncations, exceptions, illegal moves, and either side's watchdog timeout
  invalidate the batch instead of awarding Elo.
- Pair offsets compose correctly across chunks.
- Openings have stable IDs; opening and executable hashes are emitted in a manifest.
- Core rule operations use an arena-owned counter rather than trusting reported AI
  node telemetry.
- Verbose child traces are returned to the parent.
- Ultra concurrency is bounded and chunks are smaller.
- A first-legal-move audit engine lost all 16 complete control games.
- Identical-engine controls produced neutral paired scores for Easy, Medium, Hard,
  and Ultra.

## Recommended release policy

1. Functional gate: legality, tactical, mate-in-one, side inversion, exact-solver,
   timeout, and deterministic replay tests.
2. Harness qualification: trusted immutable harness; identical engine must pass,
   known inferior engine must fail, and statistical reference vectors must match.
3. Integrity gate: one fully hashed candidate/baseline/opening/harness manifest and
   zero invalid games.
4. Public short-budget arena: continue a predeclared pentanomial SPRT to a decision,
   using fresh paired openings rather than stopping at 64.
5. Holdout confirmation: independent openings at a longer work budget and real time
   control. Do not claim Elo from the tuning corpus alone.

Stockfish's Fishtest is the right operational model: paired pentanomial statistics,
predeclared sequential hypotheses, immutable engine and opening inputs, short- and
long-time-control confirmation, and independent worker quality control.
